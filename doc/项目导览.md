## 一句话项目

一个本地 coding agent：Anthropic-compatible Messages 模型 + 三个本地工具（读/写/执行命令）+ 逐次审批 + SQLite 事实源 + React 工作台。对标简化版 Claude Code，不用任何 agent 框架。

## 分层地图

依赖只能向下，不允许反向：

```
api (FastAPI 适配层)        ← 薄壳：协议校验与转发，无任何 agent 决策
 └ runtime (协调层)         ← Agent Loop / Coordinator / 审批门 / 事件发布
     ├ model (模型协议层)    ← SSE 聚合、重试、Anthropic adapter
     ├ context (上下文层)    ← 模型视图投影、预算、同步压缩
     ├ tools (工具层)        ← 路径边界 + read_file / write_file / run_command
     └ storage (存储层)      ← SQLite：唯一事实源，8 张表
core (领域层)              ← 纯类型与不变量，被所有层依赖，不依赖任何层
```

## 各模块概览

### `core/` — 领域模型（5 文件）

纯数据类型与不变量，零 IO。`models.py` 定义 Run 状态机（13 态）、停止原因（15 种，含新增的 `INTERNAL_ERROR`）、消息部件（Text/ToolUse/ToolResult/**Thinking**）、`Run`/`ToolExecution` 等冻结 dataclass。`events.py` 是唯一的状态转移表——所有转移必须经 `validate_transition` 校验。`cancellation.py` 是可等待的取消令牌。**看懂这个包就看懂了系统的词汇表。**

### `storage/` — SQLite 事实源（2 文件，1957 行）

`schema.sql` 八张表：sessions、runs、messages、model_requests、tool_executions、context_snapshots、events、client_commands。`sqlite.py` 是最大的模块，每个状态变更都是 `BEGIN IMMEDIATE` 事务：状态转移用 expected-state 条件更新（防迟到事件覆盖终态）、durable event 的 `seq` 与状态变更同事务分配、`begin_effect` 与 Stop 共享同一个线性化点、`client_commands` 按 `client_command_id` 幂等去重。启动时 `recover_interrupted_runs` 把遗留活动 run 标记 `INTERRUPTED`，不重放任何副作用。

### `tools/` — 三个本地工具（6 文件）

`paths.py` 的 `WorkspaceBoundary` 是所有工具共享的路径边界：resolve 后必须仍在 workspace 内、拒绝指向外部的符号链接。`read_file` 免审批，800 行/40KiB 双闸；`write_file` 冻结参数+基线 hash，审批后原子替换（临时文件 + fsync）；`run_command` 隔离 HOME、环境白名单（模型 API key 永不透传）、40KiB 输出上限、TERM→3s→KILL 进程组取消。**注意：run_command 不是沙箱**，批准的命令拥有你的全部用户权限——UI 有醒目警告。

### `model/` — 模型协议层（5 文件）

**这是自研含量最高的部分。** `message_assembler.py`（522 行）把 SDK 反序列化后的 SSE 事件流聚合成 `AssistantTurn`：按 block index 锁定 text/tool_use/thinking 块、`input_json_delta` 分片只在块关闭后解析、usage 取最终累计值、任何顺序冲突/身份缺失归为 `MODEL_PROTOCOL_ERROR`（不重试）。`anthropic_messages.py` 是薄 adapter：官方 SDK 只管 HTTP/认证/SSE 解码，payload 组装与消息编译（厂商无关 → wire 格式）在这里；thinking 块聚合成 `ThinkingPart` 供展示但**四条路径都排除出模型视图**（视图/wire/压缩/估算），永不回传。`retry.py` 是唯一重试所有者（SDK `max_retries=0`）：白名单状态码、`Retry-After` 解析、指数退避 30s 封顶、等待期可被 Stop 立即取消。

### `context/` — 上下文管理（4 文件）

`builder.py` 从 canonical transcript 投影模型视图：所有 user 原文逐字节保留、最近完整轮次保留、pending/draft 永不入视图、达 80% 预算触发压缩。`compactor.py` 同步摘要：先确定性裁剪旧 tool 输出，仍超则把旧 assistant/tool 组序列化成转义 JSON 交给一次无工具的模型调用；失败/空摘要不碰旧快照；60% 是软目标（`compaction_above_target`），只有超过可用预算才 `CONTEXT_OVERFLOW`。原始历史永不改写——压缩只改变发给模型的临时视图。

### `runtime/` — 协调层（6 文件）

`loop.py`（769 行）是主循环：构建视图 → 调模型 → 聚合校验 → 特殊 stop reason 分流 → 工具逐个"冻结→审批→begin_effect→执行→补结果"→ 整组原子转 committed → 下一轮。轮次上限最后一轮无工具并强制总结；重复调用指纹防 doom loop；不可用参数经 `tool_argument_retries` 回灌自纠。`coordinator.py` 全进程单活动 run 的所有权与 Stop 线性化。`approval.py` 审批门（Approve once/Reject/`--yes` 全审计）。`publisher.py` 事件广播：durable 事件先落库再广播，`assistant.delta`/`thinking.delta` 等瞬时事件不落库。`metrics.py` 只读投影出 `run-report-v1`。

### `api/` — FastAPI 适配层（6 文件）

REST 只做 bootstrap/目录/会话/快照；WebSocket 是单会话的双向控制流。`websocket.py` 的重连握手：同一 read transaction 里取快照 + `snapshot_seq`，前端应用后只接受更大的 seq——断线不丢事件也不重复。安全边界：只监听 127.0.0.1、生产模式同源校验（Host + Origin）、改状态命令必须带 bootstrap 签发的 CSRF token（重启即失效）、token 不落库不进浏览器持久存储。

### `evaluation/` — 评测 harness（5 文件）

manifest 校验（含 baseline/oracle 摘要钉死）、runner（以子进程调用正式 CLI，每次运行全新 workspace + 隔离 data-dir，oracle 在 workspace 外运行，gold/提示永不进模型上下文）、report（`strict_success` 五条件全满足才算过，usage 缺失记 null 不冒充）。`--dry-run` 不碰模型。**P0 已交付 4 个公开任务各 1 次的 smoke 基础设施；12×3 campaign 是 P1。**

### `web/` + `e2e/` — React 工作台

三栏布局：左（workspace/会话）、中（对话时间线 + 固定审批坞 + 输入框）、右（运行状态/模型/轮次/token/停止原因）。前端只渲染后端状态，不自造状态机：Send↔Stop 原位切换、审批卡展示冻结参数（diff/命令/生效 cwd/超时/非沙箱警告）、thinking 折叠框（流式展开、块结束自动折叠、历史默认折叠）。断线→限退避重连→重订阅恢复。E2E 用 ScriptedModel 驱动真实后端 + 真实 Chromium：完整链路、Stop、断线、重启 token 失效、多轮时间线顺序共 5 条。

## 一条消息的完整旅程

```
浏览器 Send → WS run.start（带 client_command_id 幂等）
  → Coordinator 认领（全局唯一活动 run）
  → Loop: Builder 投影视图（需要时 Compactor 先压缩）
  → Adapter 发请求（中性字段集；百炼返回 thinking 块）
  → Assembler 聚合成 AssistantTurn（thinking → 展示用 part）
  → 有工具调用？→ 冻结参数 → 审批坞弹卡 → 你点 Approve
  → begin_effect 线性化（与 Stop 竞争唯一临界区）
  → 工具执行（真实读/写/命令）→ 结果回灌
  → 整组原子 committed → 下一轮，直到无工具调用 → COMPLETED
每一小步：SQLite 先落库，再广播给前端。刷新页面 = 快照 + 补发事件。
```

## 设计决策速答（面试可能被问）

- **为什么自己写 SSE 聚合而不用 SDK 的高层 API？** 题目要求"模型输出的解析"自研；SDK 只做传输层，聚合/校验/错误分类是评分核心。
- **为什么同步压缩而不是异步？** P0 优先正确性；异步需要 revision/CAS 防过期覆盖（P1）。原始历史永不改写，压缩只影响临时视图。
- **为什么 thinking 不回传？** 语义上它是模型内部独白，不是对话历史；实测百炼接受不含 thinking 的回传历史。
- **为什么全局单活动 run？** 简化所有权与副作用追踪；第二个会话的发送请求被明确拒绝而非排队。
- **为什么 SQLite 是唯一事实源？** 可审计、可恢复、事务边界清晰；前端是纯投影，断线/重启都从快照重建。
