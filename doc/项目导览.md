# 项目导览(给你自己看)

> 面向项目作者的快速导览 + 面试准备手册:每个模块是什么、放在一起如何运转、去哪里找证据、面试官可能问什么。
> 权威契约仍是 `doc/项目设计方案.md`(spec)与 `doc/2026-08-27-my-coding-agent-实施计划.md`(plan);本文是它们的"地图版",冲突以 spec 为准。

## 一句话项目

一个本地 coding agent:Anthropic-compatible Messages 模型 + 四个本地工具(read_file / write_file / run_command / skill)+ 逐次审批 + SQLite 唯一事实源 + React 工作台 + 确定性评测 harness。对标简化版 Claude Code,不用任何 agent 框架。

## 分层地图

依赖只能向下,不允许反向;evaluation 层不参与运行链路,只以子进程驱动正式 CLI:

```
api (FastAPI 适配层)        ← 薄壳:协议校验与转发,无任何 agent 决策
 └ runtime (协调层)         ← Agent Loop / Coordinator / 审批门 / 事件发布 / 指标投影
     ├ model (模型协议层)    ← SSE 聚合、重试、Anthropic adapter
     ├ context (上下文层)    ← 模型视图投影、预算、同步压缩
     ├ tools (工具层)        ← 路径边界 + read_file / write_file / run_command / skill
     └ storage (存储层)      ← SQLite:唯一事实源,8 张表
core (领域层)               ← 纯类型与不变量,被所有层依赖,不依赖任何层
evaluation (评测层)         ← 独立 CLI;跑正式 headless 入口的子进程,只读消费其结果
```

## 各模块概览

### `core/` — 领域模型(5 文件)

纯数据类型与不变量,零 IO。`models.py` 定义 Run 状态机(13 态)、停止原因(16 种,含 `INTERNAL_ERROR`)、消息部件(Text/ToolUse/ToolResult/**Thinking**)、`Run`/`ToolExecution` 等冻结 dataclass。`events.py` 是唯一状态转移表——所有转移必须经 `validate_transition` 校验,终态不可迁出。**看懂这个包就看懂了系统的词汇表。**

### `storage/` — SQLite 事实源(2 文件,约 2.4k 行)

`schema.sql` 八张表:sessions、runs、messages、model_requests、tool_executions、context_snapshots、events、client_commands。`sqlite.py` 是最大模块,每个状态变更都是 `BEGIN IMMEDIATE` 事务:状态转移用 expected-state 条件更新(防迟到事件覆盖终态)、durable event 的 `seq` 与状态变更同事务分配、`begin_effect` 与 Stop 共享同一个线性化点(条件:`effect_started_at IS NULL` + queued + approved + run 未取消)、`client_commands` 按 `client_command_id` 幂等去重(同 id 同 payload 返回原 ACK,异 payload 报 `COMMAND_ID_CONFLICT`)。启动时 `recover_interrupted_runs` 把遗留活动 run 标记 `INTERRUPTED/SERVER_RESTART`:TOOL_RUNNING 的当前调用标 `unknown`、等待审批的标 `cancelled`、后续 queued 标 `skipped`,可能有副作用的 session 置 `requires_recovery_ack=1` 阻断新 run;**绝不重放任何副作用**。

### `tools/` — 四个本地工具 + 工作区上下文(8 文件)

`paths.py` 的 `WorkspaceBoundary` 是所有工具共享的路径边界:拒绝 `..`、realpath 解析(缺失叶子按最近现存祖先)、指向 workspace 外的符号链接一律拒绝、workspace 创建时固定不变。`read_file` 免审批,800 行/40KiB 双闸、1-based offset、不带行号前缀(为 replace 的精确匹配解耦)。`write_file` 集两态:`write` 整写 + `replace` 定向替换(默认恰好命中一次,`replace_all` 放宽);prepare 冻结参数 + unified diff 预览 + baseline sha256;**新鲜度闸**:已存在文件必须本 session 读过且内容未变——从未读过报 `READ_FRESH_REQUIRED`,读后或批准后被外部改动报 `WRITE_CONFLICT`;同目录临时文件 + fsync + 原子 rename + 父目录 fsync。`run_command` 隔离 HOME、环境白名单(模型 API key 永不透传)、stdout/stderr 合并 40KiB 统一上限(UI/DB/模型同一份缓冲)、进程组 TERM→3s→KILL;**它不是沙箱**,批准的命令拥有当前用户全部权限,UI 与 README 均明示。`skill` 只读免审批:`<workspace>/.agents/skills/<name>/SKILL.md` 一层扫描,frontmatter 校验(name 须等于目录名,description 1–1024 字符),无效技能跳过并发 `skill.invalid` 诊断事件;`read`(默认)返回正文+伴生文件清单,`list` 返回索引,未知名报 `UNKNOWN_SKILL`。`workspace_context.py` 在**每次 run 开始**(非 session 创建)重读工作区 `AGENTS.md`(也认小写,>128KiB 截断)与技能索引,注入 system prompt 末尾。

### `model/` — 模型协议层(5 文件)

**自研含量最高的部分。** `message_assembler.py` 把 SDK 反序列化后的 SSE 事件流聚合成 `AssistantTurn`:按 block index 锁定 text/tool_use/thinking 块,`input_json_delta` 分片只累积、在 `finish()` 统一解析;usage 取 `message_start` 与 `message_delta` 的非空字段覆盖合并、**绝不逐事件相加**;缺 `message_stop`、index/身份冲突、未知 block 类型均 `MODEL_PROTOCOL_ERROR` 且不重试。stop_reason 分流:`max_tokens`+tool_use → `INCOMPLETE_TOOL_CALL`(不执行、不入库、不走重试);纯文本 `max_tokens` → `OUTPUT_TRUNCATED`;`refusal` → `MODEL_REFUSAL`;`pause_turn` → `STOPPED/PAUSE_TURN`(P0 不续跑);`model_context_window_exceeded` → 强制压缩重建一次,再犯 `FAILED/CONTEXT_OVERFLOW`。`anthropic_messages.py` 是薄 adapter:官方 SDK 只管 HTTP/认证/SSE 解码(`max_retries=0`),消息编译(厂商无关 → wire)在这里;thinking 块**三重防回传**(wire 编译跳过、token 估算计零、压缩载荷剔除)。`retry.py` 是唯一重试所有者:`x-should-retry` 决定是否重试,`retry-after-ms`→`Retry-After` 决定延迟(>60s 回退本地);本地 2s 指数 + 25% 抖动 + 30s 封顶 + 5 次含首次;等待期 UI 可见且可被 Stop 立即打断。

### `context/` — 上下文管理(4 文件)

`builder.py` 从 canonical transcript 投影模型视图:可用预算 = `context_window − max_output_tokens − safety_margin(2048)`;估算 `ceil(utf8 字节/3)`+协议开销(估算器 id `utf8-bytes-over-3-v1`,明示是启发式);所有 user 原文逐字节保留且恒为 mandatory、最近完整轮次保留、pending/draft 永不入视图、assistant tool_use 与其全部 tool result 原子不可拆;达 80% 触发压缩;mandatory 超预算在任何模型调用前直接 `CONTEXT_OVERFLOW`。`compactor.py` 同步压缩:先确定性裁剪旧 tool 输出(占位符含工具名/状态/目标/原始字节数),仍超则把旧 assistant/tool 组序列化为转义 JSON 交一次无工具模型调用,产出固定 8 字段 JSON 摘要(见 `prompts/compact.md`);60% 是软目标(被 mandatory 下限钳制,超出记 `compaction_above_target=true`);新快照版本递增、记录来源事件 ID,失败/空摘要保留旧快照——**原始历史永不改写,压缩只改发给模型的视图**。

### `runtime/` — 协调层(6 文件)

`loop.py` 主循环:构建视图(需要时先压缩)→ 流式调模型 → 聚合校验 → 特殊 stop reason 分流 → 工具逐个"冻结→审批→begin_effect→执行→补结果"→ 整组原子转 committed → 下一轮。轮次上限 `max_rounds=30`(配置校验强制 ≥2):前 29 轮带工具,**第 30 轮不带 tools 且 system 追加"直接总结"指令**;末轮仍发 tool_calls 则整体丢弃(不落库),以 `STOPPED/MAX_ROUNDS` + `error_kind=MODEL_PROTOCOL_ERROR` 收尾。防循环:对**整轮 tool_calls 列表**的 canonical JSON 取 sha256 指纹,连续第 3 次相同不执行、回灌 `REPETITION_DETECTED` 工具错误让模型自纠,再犯第 4 次 `STOPPED/DOOM_LOOP`;参数完整但非法按连续错误**轮次**计数,第 3 个连续错误轮同样 `STOPPED/DOOM_LOOP`;空响应语义重试一次,连续两次空 `STOPPED/EMPTY_RESPONSE`。`coordinator.py` 全进程单活动 run 的所有权与 Stop 线性化(Stop 先落库 `cancellation_requested_at`+`CANCELLING`,再触发内存令牌)。`approval.py` 审批门:`--yes` 与逐次批准都产生完整审计事件。`publisher.py` 事件广播:durable 事件先落库再广播,每订阅 256 缓冲、溢出以 4408 关闭;`assistant.delta`/`thinking.delta`/`tool.output.delta` 瞬时事件带 `draft_epoch`、不落库。`metrics.py` 只读投影 `run-report-v1`(final_assistant_text 上限 8000 字符;工具参数只导出 args_hash;model_identity 取自本 run 配置快照,不含凭据与 base_url)。

### `api/` — FastAPI 适配层(6 文件)

REST 只做 bootstrap/目录/会话/快照/评测只读;WebSocket 是单会话双向控制流。安全边界:只监听 127.0.0.1;Host 校验(含实际端口)+ Origin 校验;`GET /api/bootstrap` 签发进程级随机 CSRF token(不落库、不进浏览器持久存储、重启即失效);REST 变更走 `X-CSRF-Token` 头,**WS 凭据是第二个 subprotocol 值**(`["coding-agent", token]`);自定义关闭码 4401(认证失效,前端清 token 重取一次)/4403/4408。重连握手:每会话 publisher 锁内同一读事务取 snapshot + `snapshot_seq` 并注册订阅,前端应用后丢弃 `seq ≤ lastSeq`——不漏不重。命令类型八种:subscribe / run.start / run.stop / approval.resolve / ack_recovery / compact / clear / set_approval_mode,全部带 `client_command_id` 幂等。`schemas.py` 全部 DTO `extra="forbid"`。

### `evaluation/` — 评测 harness(9 文件)

`manifest.py` 静态校验:任务路径不得出 manifest 目录、钉死 baseline 树 hash 与两个 oracle 内容 hash、allowed/forbidden 路径不重叠、commands 字段逐条精确(格式/cwd 相对/不重复;评测已不设命令白名单)。`runner.py` 以子进程驱动**正式发布的 CLI**(不 import loop),每 repeat 全新 workspace 拷贝 + 独立 `--data-dir`;跑前做三态验证(baseline 必须败 target 过 regression、gold 双过、error 变体败 target,失败记 `HARNESS_SETUP` 不计入能力分母);oracle 永远在 workspace 外执行(cwd 校验,退出码非 0/1 即 `HARNESS_ORACLE_ERROR`);canary 文件 + baseline 树重哈希检测越界;结果目录非空即拒绝写入,记录永不覆盖。`report.py`:`strict_success` 五条件(目标过 + 回归过 + 无禁区改动 + 无越界 + `COMPLETED`),另报 `artifact_correct` 把产物质量与 loop 控制质量分开;`(failure_stage, failure_kind)` 固定词表。`judge.py` 自研 LLM 裁判(复用同一 Messages adapter,无第三方评测框架):只看脱敏摘录(run-v1 字段 + 脱敏最终回复),三轴 1–5 分 + 理由,畸形 JSON 恰好重试一次,`judge_error` 永不中断 campaign;输出预算 4096(给推理留足 headroom 的修复,见 Q29)。`history.py` 只读 campaign 索引(损坏降级为备注);`web.py` 只读 `/api/evaluations/*`(GET only,仍过 Origin 校验);`tasks_extra.py` 证明公开集是 4 类 × 3 的完整矩阵。

### `web/` + `e2e/` — React 工作台

三栏布局:左(会话/工作区/评测入口,可折叠成轨道+拖拽调宽)、中(对话时间线 + 固定审批坞 + 输入框)、右(运行详情:状态/模型/会话累计的运行次数·轮次·重试·token 四项/停止原因 + 会话级上下文加载清单;窄屏变 modal drawer)。前端只渲染后端状态:`useReducer` 是唯一事实入口,组件不自行推断 run 状态;流式草稿按 `draft_epoch` 累积,与 committed 消息是不同数据。Composer:Send/Stop 原位切换(CANCELLING 显示禁用的"正在停止")、`/clear` `/compact` 斜杠菜单(listbox 键盘可达)、auto_approve 开关、recovery 确认按钮。ApprovalDock:write 类展示 unified diff,command 类展示冻结的命令/cwd/理由/超时(元数据优先于模型 input)。ThinkingDisclosure:流式展开、块闭信号自动折叠("思考完成 · N 字")、历史默认折叠;自动跟随滚动只在读者主动上滑(滚轮/触摸)时解除、回到底部重新钉住。ContextGauge:60% 琥珀/80% 红,对齐压缩阈值。评测看板 `#/evaluations` hash 路由三屏(campaign 列表/详情/单 run + JudgementCard),手写 SVG 条形图,无图表库。markdown 渲染用 react-markdown+GFM,禁 innerHTML、只放行 http(s) 链接。视觉:单手 `styles.css` "Lit Console" 浅色主题(WCAG AA)、自托管 OFL 字体、motion 弹簧词表 + 遵循系统 reduced-motion;UI 文案全简体中文。E2E 用 ScriptedModel 驱动真实后端 + 真实 Chromium:完整链路、Stop 三态、断线不取消、重启 token 失效+recovery ack、多轮时间线顺序、UX 细节共 4 个 spec 9 条。

## 一条消息的完整旅程

```
浏览器 Send → WS run.start(带 client_command_id 幂等)
  → Coordinator 认领(全局唯一活动 run)
  → run 开始:扫描工作区 AGENTS.md + .agents/skills 索引,注入 system
  → Loop: Builder 投影视图(达 80% 先 Compactor 同步压缩)
  → Adapter 发请求(中性字段集;兼容服务可返回 thinking 块)
  → Assembler 聚合成 AssistantTurn(thinking → 展示用 part,永不回传)
  → 有工具调用?→ 冻结参数+diff/命令事实 → 审批坞弹卡 → 你点 Approve
  → begin_effect 线性化(与 Stop 竞争唯一临界区)
  → 工具执行(真实读/写/命令)→ 结果回灌
  → 整组原子 committed → 下一轮,直到无工具调用 → COMPLETED
每一小步:SQLite 先落库,再广播给前端。刷新页面 = 快照 + 按 seq 补发事件。
```

## 面试问答(预设问题 + 参考答案)

### A. 总体与题目约束

**Q1:为什么不用 LangChain / Claude Agent SDK 这类框架?**
题目明令禁止 agent 框架/SDK,且"重要逻辑自行编写"是评分点。我只用官方 `anthropic==1.1.0` 客户端做 HTTP/认证/SSE 解码(SDK 内设 `max_retries=0`),消息编译、流式聚合、重试、循环终止全部自研。调研还发现这层恰恰是参照实现藏起来的部分(OpenCode 会话层 `JSON.parse` 出现 0 次,分片累积在下层库里)——自己写才能真正掌控正确性。

**Q2:整体架构是什么?**
事件驱动模块化单体:一个 FastAPI 进程、一个 React 应用、一个 SQLite,无队列无 RPC。单向依赖 `api → runtime → {model, context, tools, storage} → core`;core 是纯领域层,零 IO,被所有层依赖。评测层不进运行链路,只以子进程驱动正式 CLI。

**Q3:为什么 SQLite 是唯一事实源?**
可审计、可恢复、事务边界清晰。所有状态变更先 `BEGIN IMMEDIATE` 落库再广播,durable event 的 seq 与状态变更同事务分配;前端是纯投影,刷新/断线/重启都从快照 + seq 补发重建。JSONL/CSV 只作只读导出,杜绝双写不一致。

**Q4:为什么全局只允许一个活动 run?**
副作用所有权和 Stop 线性化因此可证明正确:`begin_effect` 与 Stop 竞争同一临界区,谁先到谁赢。第二个会话的发送被明确拒绝而非排队。代价是不能并行任务——P0 范围克制,并发是 P1。

**Q5:为什么只支持 Anthropic Messages 单协议?**
用协议边界换深度:SSE 聚合、tool_use 配对、usage 语义都按一个协议做扎实。core 与 SQLite 保存厂商无关语义,只有 adapter 编译 wire 格式;换兼容服务(官方/百炼等)只改配置三字段,实测过两种服务。OpenAI Chat Completions 等第二协议明确不做,审计脚本会扫协议残留。

### B. 题目点名的五轴

**Q6(A 轴):上下文怎么管理、怎么压缩?**
可用预算 = 窗口 − 输出预算 − 安全余量;估算是 `ceil(utf8字节/3)` 加协议开销的启发式(明示不是上界,运行时记录与 provider usage 的误差用于校准)。达 80% 触发:先确定性裁剪旧工具输出(占位符保留工具名/状态/目标/原始大小),仍超则同步 LLM 摘要——独立的无工具请求、固定 8 字段 JSON、摘要自身有独立预算。60% 是软目标,被 mandatory 下限钳制;所有 user 原文逐字保留,mandatory 超预算在任何模型调用前直接 `CONTEXT_OVERFLOW`,绝不牺牲用户输入。摘要失败/为空保留旧快照。

**Q7(A 轴):为什么同步压缩而不是异步?**
OCR 的 60% 异步 + 80% 同步双阈值更省延迟,但异步需要 revision/CAS 防过期摘要覆盖新上下文(OpenCode 用 `summary` 标记 + `previousSummary`,仍有已知的注释/实现不一致)。P0 优先可证正确:同步语义简单、失败不碰旧快照;异步压缩连同 revision 设计列在 P1。

**Q8(B 轴):工具集怎么定的?为什么没有独立 edit/grep?**
四个工具:read_file / write_file / run_command / skill。定向替换并入 write_file 的 `replace` 操作(默认恰好命中一次)而非独立 edit:OpenCode 的 `edit.ts` 是 `write.ts` 的 7.1 倍行数,且带行号的 read 会污染 `oldString`(它专门花一段提示词教模型剥前缀)——我们的 read_file 干脆不出行号,耦合从源头消失。搜索由 run_command + rg 覆盖:Codex 在 2026-08 已收敛到单一 exec 工具,Claude Code 的 Glob/Grep 也都是免权限读类工具。skill 工具按 OpenCode 模式做按需加载:索引常驻、正文不常驻。

**Q9(B 轴):write_file 怎么防盲写和竞态?**
三道:① prepare 冻结参数 + unified diff 预览 + baseline sha256,前端只能批准/拒绝、改不了参数;② 新鲜度闸——已存在文件必须本 session 读过且 hash 未变(没读过 `READ_FRESH_REQUIRED`、读后变了 `WRITE_CONFLICT`,新文件与自己刚写的豁免);③ 批准后执行前再核 baseline,同目录临时文件 + fsync + 原子 rename + 父目录 fsync。这是 DSH `replaceIfVersion` 的 CAS 语义(防外部修改),而不是 OpenCode 已删除的"读过没有"布尔。

**Q10(B 轴):run_command 的执行模型?**
明确**不是沙箱**(README 与 UI 都提示)。POSIX 进程组(`start_new_session`),超时/停止先 TERM、3 秒宽限后 KILL;stdout/stderr 合并,UI/数据库/模型共享同一份 40KiB 上限缓冲,记录原始字节数与截断标记;子进程环境白名单(PATH/locale/临时目录 + 隔离 HOME + 显式 pass_env),模型密钥永远剔除。headless 无人值守必须给 `--yes` 与 `--ack-unsafe-auto-approve`,否则启动前 CONFIG_ERROR;`--command-policy`(command+cwd 精确匹配,无 glob)可选,传了则必须非空——评测默认不传、命令不设限。

**Q11(B 轴):路径边界怎么做?**
所有工具只经 `WorkspaceBoundary` 取路径:拒绝 `..`,realpath 解析(缺失叶子按最近现存祖先),指向 workspace 外的符号链接一律拒绝,workspace 创建时固定。P0 面向非对抗环境,执行前重新 resolve + baseline hash 防普通外部修改;dirfd/O_NOFOLLOW 强 anti-TOCTOU 加固在 P1。

**Q12(C 轴):流式解析怎么做的?(最核心)**
`MessageStreamAssembler` 把 SSE 事件聚合成 `AssistantTurn`:block 按 index 建立并锁定(text/tool_use/thinking);`input_json_delta` 只累积,整条消息校验完才解析;usage 取最终累计值绝不逐事件相加;缺 `message_stop`、index/身份冲突、未知 block 类型都是 `MODEL_PROTOCOL_ERROR` 且不重试。这一层 OpenCode 藏在下层库(会话层不碰分片),禁用 SDK 高层能力后必须自己写——所以它是评分核心,也是调研判定"最容易低估工作量"的一轴。

**Q13(C 轴):工具参数坏了怎么办?**
三分流:① 完整但非法 → 普通 tool error 回灌让模型自纠,连续错误轮超 2 次 → `STOPPED/DOOM_LOOP`;② `max_tokens` 截断且含 tool_use → `INCOMPLETE_TOOL_CALL`,不执行、不入库、不走重试(pydantic-ai #3118 证明回灌重试对截断无效——模型不知自己被截断,会原样重试烧光预算;我们比它的修复更早分流);③ 纯文本 `max_tokens` → `OUTPUT_TRUNCATED`,截断文本保留展示。

**Q14(C 轴):thinking 块怎么处理?**
聚合成 `ThinkingPart`,UI 流式展开、块闭自动折叠、历史默认折叠;但**永不回传模型**,三重防线:wire 编译跳过、token 估算计零、压缩载荷剔除。语义上它是模型内部独白不是对话历史;实测兼容服务接受不含 thinking 的回传。

**Q15(D 轴):循环凭什么终止?**
主判据是"本轮无合法 tool calls",**不信 stop_reason**——OpenCode 源码注释直陈有 provider 在含 tool calls 时仍返回 stop,双向工单(早停/跑飞)都存在。文本+工具混合时工具优先继续。没有 complete/task_done 工具:OCR 的强契约适合一次性审查流,交互式 agent 里"模型说完话就结束"才是用户预期。

**Q16(D 轴):轮次上限怎么落地?**
`max_rounds=30`(配置校验强制 ≥2,保证收尾轮必然存在):前 29 轮带工具,第 30 轮**不带 tools** 且 system 追加"直接总结"指令,以 `STOPPED/MAX_ROUNDS` 收尾;末轮仍发工具则整体丢弃并记 `MODEL_PROTOCOL_ERROR`。这是机制化硬停——对照 OpenCode V1 的纯提示词软着陆(tools 照传)和 OCR 的收窄工具 grace round,我们取"最后一轮无工具"这个最简机制。

**Q17(D 轴):死循环怎么防?**
对**整轮** tool_calls 列表的 canonical JSON 取 sha256 指纹:连续第 3 次相同不执行,回灌 `REPETITION_DETECTED` 工具错误让模型自纠;再犯第 4 次 `STOPPED/DOOM_LOOP`。OpenCode 命中后是问人(permission ask),OCR 是连续空轮直接停;无交互场景我们选"回灌自纠、再犯才停"。另:连续两次空响应 → `STOPPED/EMPTY_RESPONSE`。

**Q18(E 轴):错误处理的总体哲学?**
工具层一切坏事都是普通 tool result 回灌(OCR 二分法:只有模型宣布失败才是进程级错误),模型能自纠就不打断 run。模型层只有三类结构化异常:传输/API/协议;协议错误绝不重试。不可恢复仅三种:认证/配置、重试耗尽、压缩后仍溢出——进 `FAILED` 且完整历史保留,修复后同 session 可继续。

**Q19(E 轴):重试策略?**
SDK `max_retries=0`,`RetryingInvoker` 是唯一重试所有者:408/409/429/5xx(显式含 529)/连接失败/超时可重试,401/403/协议错误永不;`x-should-retry` 决定是否重试,`retry-after-ms`→`Retry-After`(秒或 HTTP-date)决定延迟,服务端要求超过 60s 回退本地;本地 2s 指数 + 25% 抖动 + 30s 封顶,5 次含首次;等待期对 UI 可见(attempt + 下次时间)且可被 Stop 立即打断;流中断整轮重发(此时尚无本地副作用,不会重复)。

**Q20(E 轴):Stop 和服务重启怎么保证安全?**
Stop 先落库(`cancellation_requested_at` + `CANCELLING` + durable event)再触发内存令牌,与 `begin_effect` 共享线性化点:批准只表示"允许尝试",begin_effect 的条件事务(run 活跃 + 未取消 + 调用 queued/approved + `effect_started_at IS NULL`)赢了就执行,Stop 先赢则旧审批处理器不得再启动;已开始的按真实结果结算,已完成原子 replace 的不能改写成 cancelled。浏览器断线不取消后端 run。服务重启:遗留活动 run → `INTERRUPTED/SERVER_RESTART`,TOOL_RUNNING 当前调用标 `unknown`、等待审批标 `cancelled`、queued 标 `skipped`,补齐全组转 committed 保证历史合法;可能有副作用的 session 置 `requires_recovery_ack` 阻断新 run,用户确认"已检查工作区/进程"后才放行。**任何路径都不重放副作用。**

### C. 安全与审批

**Q21:审批机制怎么设计?**
write_file/run_command 逐次审批,read_file/skill 免审批。prepare 时冻结全部参数与展示事实(write 的 diff、command 的命令/cwd/理由/超时),前端只能 approve/reject,改不了冻结参数;Reject 当前调用标 rejected、同批剩余标 skipped 并回灌模型重新规划。`--yes` 受信任模式仍产生完整审计事件;另有每会话持久化的 auto_approve 开关(变更写 durable event)。

**Q22:Web 端安全边界?**
只监听 127.0.0.1,无远程 host 开关。Host 校验(含实际端口)+ Origin 校验;bootstrap 签发进程级随机 CSRF token,不落库、不进浏览器持久存储、重启即失效(WS 以 4401 关闭,前端清 token 重 bootstrap 一次再订阅)。REST 变更走 `X-CSRF-Token` 头,WS 凭据是第二 subprotocol 值。`--yes` 不绕过任何一项。没有浏览器在线时绝不自动批准。

**Q23:凭据怎么管?**
密钥只从 config 指名**变量名**的环境变量读取;配置快照、日志、报告、评测文档只含变量名;run_command 子进程环境永远剔除模型密钥。发布门禁 `scripts/audit_public.py` 扫工作树(可加 `--history` 扫全史)的凭据/禁路径/内部痕迹/第二协议残留,命中只报规则号与位置、不回显原文;`check_readme_txt.py` 卡 README.txt 的 1000 字/code point、URL、运行步骤与功能摘要。

### D. 前后端协议与状态同步

**Q24:断线重连怎么做到不漏不重?**
每会话 publisher 锁内:同一读事务取 snapshot + `snapshot_seq` 并注册订阅(握手期间的新事件先缓冲);前端应用快照后丢弃 `seq ≤ lastSeq` 的 durable 事件。瞬时 delta(文本/thinking/工具输出)带 `draft_epoch` 不落库,重连即弃旧草稿。durable 事件到达还触发 REST snapshot 兜底刷新(合并 + 有界退避)。E2E 覆盖:刷新恢复、断线不取消、重启 token 失效。

**Q25:命令幂等怎么实现?**
每条客户端命令带 `client_command_id`:receipt、领域变更、ACK/event 在**同一事务**提交。断线重发同 id 同 payload → 返回原 ACK,不重复建 run/审批/副作用;同 id 异 payload → `COMMAND_ID_CONFLICT`。禁止"先 claim 再另开事务执行"的写法。

**Q26:前端架构要点?**
无路由库(hash 路由)、无 UI/图表库(手写 SVG 条形图)、无 CSS 框架(单手 styles.css)。`useReducer` 是唯一事实入口,组件不自行推断 run 状态;流式草稿与 committed 消息是不同数据。全简体中文 UI,ARIA 完整(listbox/dialog/status),遵循系统 reduced-motion,浅色 "Lit Console" 主题 + 自托管 OFL 字体。

### E. 评测

**Q27:评测 harness 怎么设计?**
只以子进程驱动**正式发布的 headless CLI**(不 import 任何私有逻辑——评的就是交付路径)。每 repeat 全新 workspace 拷贝 + 独立 `--data-dir`;oracle 在 workspace 外执行(cwd 强制校验),退出码非 0/1 即 harness 错误;canary 文件 + baseline 树重哈希检测越界;manifest 钉死 baseline/oracle 内容 hash。跑前自动三态验证(baseline 必须败 target 过 regression、gold 双过、error 变体败 target),失败记 `HARNESS_SETUP` 不进能力分母。结果永不覆盖,非空输出目录直接拒绝。

**Q28:成功怎么定义?**
主指标 `strict_success` 五条件同时成立:目标 oracle 过 + 回归 oracle 过 + 无禁区改动 + 无越界 + run 以 `COMPLETED` 结束。另报 `artifact_correct`(产物对但 run 没收尾,如 MAX_ROUNDS)——把产物质量与 loop 控制质量分开。失败分类是固定 `(failure_stage, failure_kind)` 词表,不从自然语言猜。

**Q29:模糊指标怎么做?**
自研 LLM judge,复用同一 Messages adapter(不引 ragas 等第三方评测框架):只看脱敏摘录(run-v1 字段 + 脱敏后的最终回复,绝不看 prompt/工具参数/工作区),三轴 1–5 分 + 理由;畸形 JSON 恰好重试一次,`judge_error` 永不中断 campaign;模糊分**永不进入** strict_success。真实教训:首跑 judge 的思考耗尽了 1024 输出预算,JSON 根本没产出,12 份里 4 份 malformed;修到 4096(commit `176cc1e`)后第二次 12/12 全有效。

**Q30:评测结果如何?**
公开任务集 12 个(新建/局部改/定位改两文件/600 行以上大文件小改,四类各 3,均带 error 变体)。2026-08-30 两次 campaign(各 12×1,模型 deepseek-v4-pro-0813):strict_success 均 **12/12**;第二次 judge 均分 task_completion 5.0 / process_quality 4.0 / communication 5.0。单 repeat 样本小,只作方向性证据;12×3 正式 campaign 与压缩消融(C0 关/C1 摘要/C2 裁剪+摘要)在 P1。

### F. 取舍、风险与后续

**Q31:最大的已知风险是什么?**
整文件 write 的 `content` 撞 `max_tokens` 被截断:分流 `INCOMPLETE_TOOL_CALL`、不执行不入库、提示拆小。大文件小改的 token 成本线性放大是已知代价——公开任务集里 T4 类(600 行以上文件小改动)专门占 3 个权重来暴露它,实测该类 3/3 通过。

**Q32:明确不做什么?**
多 run 并发、子 agent/规划器、RAG/向量索引、PTY/交互 stdin、后台 job、第二协议、服务端托管工具、独立 edit/search/patch 工具、真沙箱。每条都能说放弃理由:范围克制 + 可辩护性优先,把一条主链路做到可证明正确,胜过十个半成品特性。

**Q33:P1 接着做什么?**
pause_turn continuation、非流式兼容、异步压缩(带 revision/CAS 防过期覆盖)、dirfd/O_NOFOLLOW 路径加固、12×3 正式 campaign 与压缩消融、SWE-bench Verified 固定 3 实例 smoke。P1 失败不阻塞 P0 交付。

## 已知边界(诚实清单)

- 路径边界面向非对抗环境;dirfd/`O_NOFOLLOW` 强加固在 P1。
- `run_command` 不是沙箱;主动 setsid/daemonize 脱离进程组的后代不在 P0 强保证范围。
- 交互式命令(等 stdin)与超长任务只能等超时;无 PTY、无后台 job。
- `pause_turn` 不自动续跑(P0 收 STOPPED);只支持 `stream=true`;不支持 OpenAI Chat Completions 等第二协议。
- token 估算是 `ceil(utf8字节/3)` 启发式,不当上界;以 provider usage 为准并记录估算误差。
- 末轮(无工具轮)模型仍发 tool_calls 时整体丢弃不落库——max_tokens/refusal/pause_turn 都会留存 interrupted 文本,这条路径有意不留。
- live 四场景(新建/修改/自纠/第二协议兼容服务)的离线门控已验证(skip 路径不触网),真实模型冒烟尚未执行。
- 历史里有一次误提交:`248257b` 曾把 `.superpowers/` 下的中文实施报告入库,已在后续提交取消跟踪、**未改写历史**;`audit_public.py --history` 会报 PATH001 的 history-only 信号(exit 2),CI 门禁只扫工作树保持绿。
- 评测证据是 12 任务 × 1 次,judge 与主跑共用同一模型(自评偏差已知);campaign 记录(脱敏 run 文档 + per-run 数据库)已入库作证据。
